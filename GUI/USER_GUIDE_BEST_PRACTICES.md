# 使用指南和最佳实践

## 1. 快速开始

### 1.1 环境准备
```bash
# 编译C++后端
cd /home/zjj1551/LR
make lr_cli

# 启动GUI
cd GUI
python3 GUI.py
```

### 1.2 基本操作流程
1. **输入文法** - 在左侧文法输入区域输入产生式
2. **选择算法** - 选择LR(0)、SLR(1)或LR(1)分析器
3. **构造分析表** - 点击"构造分析表"按钮
4. **查看结果** - 在右侧标签页查看ACTION表、GOTO表、项目集
5. **分析输入串** - 输入待分析字符串并执行分析
6. **导出报告** - 将完整结果导出为文件

## 2. 文法编写规范

### 2.1 基本语法
```
# 标准格式
E -> E + T
E -> T
T -> T * F
T -> F
F -> ( E )
F -> a
```

### 2.2 注意事项
- 每行一个产生式
- 使用 `->` 分隔左部和右部
- 符号间用空格分隔
- 不支持空产生式(ε产生式)
- 开始符号默认为第一个产生式的左部

### 2.3 常见错误
❌ **错误示例**:
```
E->E+T          # 缺少空格
E → E + T       # 使用了中文箭头
E -> E + + T    # 连续终结符
```

✅ **正确示例**:
```
E -> E + T
E -> T
T -> id
```

## 3. 算法选择指南

### 3.1 LR(0)分析器
- **适用场景**: 简单的无歧义文法
- **优点**: 算法简单，状态数少
- **缺点**: 适用范围有限，容易产生冲突
- **推荐**: 教学演示、简单语言设计

### 3.2 SLR(1)分析器
- **适用场景**: 大多数实用文法
- **优点**: 兼容性好，性能适中
- **缺点**: 比LR(1)限制更多
- **推荐**: 一般项目的首选算法

### 3.3 LR(1)分析器
- **适用场景**: 复杂文法、商业编译器
- **优点**: 最强大，支持最广泛的文法
- **缺点**: 状态数多，内存消耗大
- **推荐**: 复杂语言、高性能要求

## 4. 冲突解决策略

### 4.1 移进-归约冲突
**问题识别**:
```
错误: 分析表构造失败
✗ 检测到冲突：
  移进/归约冲突在状态 5 符号 *
```

**解决方法**:
1. **算法升级**: LR(0) → SLR(1) → LR(1)
2. **文法重写**: 消除歧义
3. **优先级定义**: 添加算符优先级

**示例**:
```
# 有冲突的文法
E -> E + E
E -> E * E
E -> a

# 修改后的文法
E -> E + T
E -> T
T -> T * F
T -> F
F -> a
```

### 4.2 归约-归约冲突
**问题原因**: 多个产生式在同一状态下可归约

**解决策略**:
1. 合并相似产生式
2. 重新设计文法结构
3. 使用更强的分析算法

## 5. 性能优化建议

### 5.1 文法优化
- **减少产生式数量**: 合并相似规则
- **避免深度嵌套**: 减少递归层次
- **平衡左右递归**: 选择适当的递归方式

### 5.2 使用优化
- **批量处理**: 一次性处理多个相关操作
- **结果缓存**: 避免重复计算
- **内存清理**: 及时清空不需要的结果

## 6. 调试技巧

### 6.1 分析表调试
1. **检查ACTION表**: 查看是否有冲突项
2. **验证GOTO表**: 确认状态转移正确
3. **分析项目集**: 理解状态构造过程

### 6.2 输入串调试
1. **逐步执行**: 观察每步的状态变化
2. **栈状态检查**: 确认符号栈和状态栈一致
3. **错误定位**: 找到第一个出错的步骤

## 8. 常见问题解答

### Q1: 为什么我的文法无法构造分析表？
**A**: 检查以下几点：
- 文法格式是否正确
- 是否存在移进-归约冲突
- 尝试使用更强的分析算法

### Q2: 如何提高分析表构造速度？
**A**: 
- 简化文法结构
- 减少不必要的产生式
- 使用SLR(1)而非LR(1)

### Q3: 导出的报告包含哪些内容？
**A**: 完整报告包含：
- 文法规则
- 分析总结
- ACTION表和GOTO表
- 项目集详情
- 分析过程记录

### Q4: 如何处理大型文法？
**A**:
- 分模块设计文法
- 使用增量分析方法
- 定期清理临时数据
